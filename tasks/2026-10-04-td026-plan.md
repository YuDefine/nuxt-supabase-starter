## BDD runner 選型比較（拍板題 D5）

規約約束（`aixbdd-workflow.md` § clade 伴隨 B1/B2/B4）：runner 直接讀 `specs/truth/features/**`、
`@unverified` 預設排除、`dsl.md` ↔ 執行層雙向機械對帳。fleet 標準是 SpecFormula（`.clade/manifest.json`
已宣告 `aixbdd`＋`specformula`；「宣告即須完整覆蓋」）。

| 候選 | 成本 | 相容性 | 結論 |
| --- | --- | --- | --- |
| **A. SpecFormula＋`dsl.yml`＋custom instruction** | 接線重但一次性：pnpm workspace 接 `vendor/specformula-ts`、`/test/*` 四端點＋guard、`features/support/environment.ts`、authenticator、`specs/data` DDL＋mapping、CI job；`dsl.md`→`dsl.yml` 手動轉換有 cookbook 規則；另需 ~5 個 custom instruction 覆蓋 wire 句型（`呼叫 GET` by path、`回應狀態碼為`／`回應 data`／`回應 pagination` 斷言、`呼叫者是使用者`、`資料表沒有被查詢`、`讀取會失敗`） | truth 句型**零改動**（句型經 dsl.yml 展開成 isa 指令）；entity_setup/entity_validate 內建覆蓋 DB Given/權威狀態；`isa.yml`/`test:bdd` 與 manifest 宣告一致；`vendor/specformula-clade` 是 custom instruction 先例 | **推薦**：合 fleet 標準、句型可攜性保留 |

## 送拍板佇列的五題（每題附推薦）

> 以下各題已用 `flow ask` 送進決策佇列（span id 記於本檔「拍板收據」節）。

**D1 — id 策略（Q-profiles-1＋6）**
- **A（推薦）**：`server/auth.config.ts` 設 `advanced.database.generateId: "uuid"`（模組 `useUuid` 支援）＋ `supabase/seed.sql` 三個 id 改為合法 UUID＋更新 `docs/FIXTURES.md`。真實使用者 id 變 UUID：`profiles.id` 可存、`呼叫者是使用者` 別名可落地（Q6 硬前置解除）、`[id].get.ts` 對真實使用者不再 400、「出廠種子 id」Rule 連同 `[need clarification]` 刪除。
- B：維持 generateId 預設，`profiles.id` 改 `text`＋`profileIdParamSchema`/`profileSchema.id` 放寬 `z.string()`。不動 auth，但 id 不再是 UUID、合約變鬆、seed Rule 仍卡 Q8。
- C：只改 `seed.sql`。seed Rule 解掉但真實使用者 id 仍非 UUID，別名機制依舊無法落地——已知走不通，僅列出。

**D2 — `search` ILIKE（Q-profiles-3）**
- **A（推薦）**：視為缺陷，`index.get.ts` 接 `sanitizePostgrestSearch`；feature 移除 `[need clarification]`、「現況鎖定」Rule 改寫為跳脫後行為。
- B：現況鎖定為刻意行為——保留 Rule 標註，`sanitizePostgrestSearch` 留死碼或刪除。

**D3 — session 角色機制（Q-profiles-5＋9）**
- **A（推薦）**：授權改讀 DB 權威——`requireRole`/`[id].get.ts` 的 admin 判定改查 `profiles.role`；dev-login 建 user 後 upsert `profiles` row（`as` 映射 `member→user`、`admin→admin`），順便消滅雙值域、session 不再帶 role。配合 D1-A 的 UUID id 才能寫 `profiles.id`。
- B：Better Auth admin plugin（`session.user.role` 落地）——官方機制，但須先替 better-auth 接持久 DB adapter（目前無，user 不持久），starter 預設改動面較大。
- C：維持 member-only，admin Example 全部 `@unverified`——TD-026 acceptance 不達成，僅列出。

**D4 — dev-login 指定 id（Q-profiles-8）**
- **A（推薦，依存 D1=A）**：不擴 dev-login——字面 seed-id Rule 隨 D1-A 刪除，別名機制覆蓋其餘所有 Example；dev-login 維持最小面。
- B：dev-login body 加可選 `id`（UUID 限定，dev-only route 已有 404 guard）：字面 id 呼叫者可行；代價是動 auth 路徑，且 Better Auth 建 user 指定 id 的接法要另外驗證。

**D5 — BDD runner 選型**
- **A（推薦）**：SpecFormula＋`dsl.yml`＋custom instruction（見上表）。
- B：手寫 cucumber-js＋撤 `specformula` 宣告。
- C：改寫 truth 句型成指令式。
