## 1. TD-010 — email 登入被自家 nuxt-security CSRF 擋在 403（本 repo，需先拍板）

- **證據**（遷移後實測）：
  ```text
  $ curl -i -X POST http://localhost:3123/api/auth/sign-in/email \
      -H 'content-type: application/json' -d '{"email":"user@example.com","password":"whatever12"}'
  HTTP/1.1 403 CSRF Token Mismatch
  ```
  登入頁按下 Sign In 會顯示 `CSRF Token not found`（錯誤路徑本身是通的：
  `signIn.error` → `setError` → `UAlert`）。
- **與遷移無關**：gate 在 `nuxt-security` 的 server middleware，舊 `@onmax` 版本走同一條
  路徑，是既有缺口。CI 沒抓到是因為 `template/e2e/auth.spec.ts` 的真實登入測試在缺
  `E2E_USER_EMAIL` / `E2E_USER_PASSWORD` 時 `test.skip`，而 `auth.setup.ts` 走
  `POST /api/_dev/login`（server 端直接呼叫 `serverAuth()`，不經 client fetch）。
- **未拍板的分歧**：(a) `security.csrf` 排除 `/api/auth/**`（要先確認 Better Auth 在本專案
  設定下的 origin / cookie 防護真的啟用）；(b) 讓 client 帶上 nuxt-security 的 token。
  **NEVER** 直接關掉 `security.csrf`。
- **檔案所有權**：`template/nuxt.config.ts`（`security.csrf`）、`template/app/pages/auth/login.vue`、
  `template/e2e/auth.spec.ts`。
