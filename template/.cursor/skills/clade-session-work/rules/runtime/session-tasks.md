# Cursor task and carrier adapter

Cursor's native `Task` is progress/delegation presentation and does not replace the per-session tasks file. Use the current Cursor task events and `cursor-ide-browser` only when observed. A missing event or browser surface remains blocked; do not infer completion from an idle pane.

## Context measurement

Use the current Cursor harness context indicators and supported checkpoint or session controls. Save the objective, authorization, artifacts, evidence, and remaining work before a transition. A UI indicator is not a cumulative token budget unless its documented metric says so. This adapter does not establish a numeric launcher budget or import Claude launcher thresholds. If no measurement is exposed, record that limitation and follow the shared observable predicates.

## Writer attribution

Start with the shared `flow who` probe and verify its per-path evidence. Use only the current Cursor session/task inspection tools and actual session identifiers; on Linux, inspect a returned writer pid and its parent chain with bounded CLI probes. A task title, a filename mentioned in a transcript, an idle state, or the existence of an environment variable does not identify the writer. Native task completion or interruption does not prove that its external child processes exited. When session inspection or process correlation is unavailable, preserve unknown ownership and the existing WIP. Claude transcript fallback cannot establish absence of Cursor writers.
