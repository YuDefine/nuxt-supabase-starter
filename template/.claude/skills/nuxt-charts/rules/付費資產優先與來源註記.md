# 付費資產優先與來源註記

> 讀取時機：`nuxt-charts` SKILL.md Phase 2 step 2 判定要以什麼為底時，以及 Phase 4 step 2 寫來源註記時。

# Rule 1 - 先以 block／template 為底，自組要先證明沒有合用的

- Level: `MUST`
- 判定順序：block 或 template 涵蓋需求的資料形狀與版面（改資料來源、文案、配色、欄位數仍算涵蓋）就以它為底；涵蓋一部分也以它為底再改，**NEVER** 因為要改就放棄它。只有查過的 block／template 都對不上資料形狀或版面，才用開源 chart 自組。
- 自組時 MUST 留下查過哪些 block slug／template 名，以及每個為何不合用；這段內容同時寫進 Rule 2 的 `composed` 註記與 PR 說明。
- **NEVER** 只讀 nuxtcharts.com 的公開 docs 就手刻；**NEVER** 把「CLI 拿不到」當成自組的理由——block 與 template 都從鏡像取，block 在鏡像 STALE 或缺件時退回網站 Code（`付費內容取得路徑.md`），都失敗才算拿不到，而且要照該檔停下回報。
- 理由：fleet 已付 Full Access，手刻同類 UI 等於重做一份已經買到的東西。

## Good Example

- 這個例子是好的，因為它先對過 block，只在資料形狀不符時才自組，並把查過的寫出來。

```text
需求：某 consumer 的營收趨勢圖 → 鏡像 area-charts/area-chart-preview.png 是月營收雙序列面積圖 → 換成該 consumer 的月營收資料 → 以它為底
```

## Bad Example

- 這個例子是壞的，因為它跳過 blocks，直接照公開 docs 的 AreaChart 範例手刻。

```text
需求：某 consumer 的營收趨勢圖 → 讀 /docs/charts/area-chart → 自己寫 <AreaChart> 與卡片外框
```

# Rule 2 - 每個圖表檔第一行寫來源註記

- Level: `MUST`
- 範圍：consumer 裡**每一個**用到 nuxt-charts 圖表元件（`AreaChart`、`BarChart`、`LineChart`、`DonutChart` 等，含 kebab-case 寫法）或 `Lib` 前綴元件的 `.vue` 檔。
- 第一行是三種格式之一：

```html
<!-- nuxt-charts-source: block:<類別 slug>/<block 標題>@<鏡像短 sha> -->
<!-- nuxt-charts-source: template:<template 名>@<manifest 記的上游 commit 短 sha> -->
<!-- nuxt-charts-source: composed — checked: <查過的 block slug／template，逗號分隔>; reason: <為何不合用> -->
```

- `block` 的 `@<鏡像短 sha>` 是 `付費內容取得路徑.md` Rule 1 判定 `FRESH` 時印出的那個；鏡像 STALE 或缺件而退回網站 Code 時不寫 `@` 這段（舊檔沒有 `@` 仍有效）。`template` 的 sha 取鏡像 `manifest.json` 該 template 的 `commit` 前 7 碼。
- `composed` 的 `checked:` **NEVER** 留空。clade 的 `scripts/audit-nuxt-charts-adoption.ts` 會掃這行：沒有註記或 `checked:` 為空都列為 finding。
- 理由：沒有這行，稽核分不出圖表是用付費資產改的還是手刻的，繞過付費資產就是靜默的。

## Good Example

```html
<!-- nuxt-charts-source: block:area-charts/Area Chart Preview@1a2b3c4 -->
<script setup lang="ts">
```

## Bad Example

- 這個例子是壞的，因為 `checked:` 是空的，等於沒有查過。

```html
<!-- nuxt-charts-source: composed — checked: ; reason: 比較快 -->
```
