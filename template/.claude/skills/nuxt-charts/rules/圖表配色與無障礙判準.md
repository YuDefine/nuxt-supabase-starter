# 圖表配色與無障礙判準

> 讀取時機：`nuxt-charts` SKILL.md Phase 4 step 4，付費 block 或自組圖表落進 repo 之後、交驗證之前。

# Rule 1 - 圖表色只取 Nuxt UI 語義 token

- Level: `MUST`
- 資料色一律用 Nuxt UI 語義 token（`--ui-error`、`--ui-warning`、`--ui-text-toned`、`--ui-text-muted` 等），並集中在 consumer 的一個色彩對照檔，元件從那裡取。
- **NEVER** 寫死色碼，**NEVER** 用漸層；付費 block 自帶的色碼落地後要換掉。
- **NEVER** 把 `primary` 當資料色：primary 留給互動與狀態語意（例如「進行中」），拿來畫資料會讓兩種語意混在一起。
- v3 沒給 `color` 的 category 會依序取 `--vc-series-N`，其預設值依序是 `--chart-color-N`、再退到 `--ui-primary`、`--ui-secondary`…（3.1.0 `theme.css`），所以第一個序列不指定色就是 primary。每個 category **MUST** 明確給 `color` 並從色彩對照檔取；或在全域 CSS 把 `--chart-color-0` 到 `--chart-color-7` 全部設成非 primary 的語義 token，二擇一。
- 理由：語義 token 會跟著亮暗主題與品牌色切換，寫死的色碼不會。

## Good Example

```ts
// app/lib/chart-colors.ts
export const chartColors = { critical: 'var(--ui-error)', warn: 'var(--ui-warning)', base: 'var(--ui-text-toned)' }
```

## Bad Example

- 這個例子是壞的，因為第一組寫死色碼與漸層；第二組第一個 category 沒給 `color`，在 v3 會退到 `--ui-primary`，第二個則直接把 `--ui-primary` 當資料色。

```ts
const colors = ['#22c55e', '#3b82f6', 'linear-gradient(#f00, #00f)']

const categories = {
  orders: { name: '訂單數' },
  revenue: { name: '營收', color: 'var(--ui-primary)' },
}
```

# Rule 2 - 每張圖都要有文字替代

- Level: `MUST`
- 圖表容器加 `role="img"` 與一句說明結論的 `aria-label`。
- 在 `role="img"` 容器**外**、作為兄弟節點附一份同數字的 `sr-only` 表格，讓螢幕閱讀器讀得到每個值；**NEVER** 把表格放進 `role="img"` 裡面——img 的子節點會被當成裝飾略過。
- 負值除了顏色之外另加「−」號，不只靠顏色區分正負。

## Good Example

```vue
<div role="img" aria-label="近 8 週淨流量，第 6 週轉負">
  <BarChart ... />
</div>
<table class="sr-only">...</table>
```

## Bad Example

```vue
<BarChart ... /> <!-- 沒有 aria-label，負值只用紅色表示 -->
```

# Rule 3 - 圖表外框色在全域對 `--vc-*` 變數設定，不在單張圖覆寫

- Level: `MUST`
- 軸線、格線、刻度文字、tooltip、圖例屬圖表外框，顏色由 v3 的 `--vc-*` CSS 變數控制（例如 `--vc-grid-color`、`--vc-axis-line-color`、`--vc-tick-color`、`--vc-legend-color`、`--vc-tooltip-bg`、`--vc-tooltip-fg`、`--vc-tooltip-border`）。v2 時代的 `--vis-*` 變數在 v3 已不存在，**NEVER** 照舊範例寫 `--vis-*`。
- 有裝 Nuxt UI 時，3.1.0 的 `theme.css` 已把這些變數預設對到 Nuxt UI 語義 token（格線與軸線 → `--ui-border`，刻度與圖例 → `--ui-text-muted`，tooltip → `--ui-bg-elevated`／`--ui-text-highlighted`），亮暗主題也已處理；預設可用就不寫任何設定。
- 要調整時只在 consumer 的全域 CSS 對 `.vue-chrts` 改 `--vc-*`，值 **MUST** 指向 Nuxt UI 語義 token；套件的 `theme.css` 在 `@layer vue-chrts` 內，未分層的全域規則會蓋過它。**NEVER** 在單張圖用 `theme` prop、inline style 或 scoped CSS 改外框色——同頁的圖會長得不一樣，換主題時也只有沒覆寫的那幾張跟著變。

## Good Example

- 這個例子是好的，因為只在全域調一次，而且值仍是 Nuxt UI token。

```css
/* app/assets/css/main.css */
.vue-chrts {
  --vc-grid-color: var(--ui-border-muted);
  --vc-tooltip-bg: var(--ui-bg);
}
```

## Bad Example

- 這個例子是壞的，因為用 v2 的變數名、寫死色碼，而且只改這一張圖。

```vue
<LineChart :data="data" :categories="categories" :height="280" style="--vis-axis-grid-color: #e5e7eb" />
```
