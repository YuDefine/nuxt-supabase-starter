# 圖表類型選擇判準

> 讀取時機：`nuxt-charts` SKILL.md Phase 1 step 1，已判定要畫圖、要決定畫哪一種時。元件名以 `nuxt-charts` v3 為準。

# Rule 1 - 依資料形狀選圖種

- Level: `SHOULD`
- 先說出這張圖要回答的問題，再依資料形狀選第一個對得上的列：

| 資料形狀／要回答的問題 | 用哪個元件 |
| --- | --- |
| 隨時間變化，比較多條序列的走勢 | `LineChart` |
| 隨時間變化，看單一總量或堆疊組成 | `AreaChart` |
| 分類之間比大小（類別標籤長或超過 7 類時改水平方向） | `BarChart` |
| 整體的佔比，類別 ≤ 5 | `DonutChart` |
| 依序階段的轉換與流失 | `FunnelChart` |
| 來源到去向的流量分配 | `SankeyChart` |
| 單一指標對目標的達成度 | `RadialBarChart` |
| 同一對象在多個指標上的輪廓 | `RadarChart` |
| 兩個數值變數的關係（第三維用大小） | `BubbleChart` |
| 開高低收 | `CandlestickChart` |
| 一段期間內的可用率或逐日狀態 | `StatusTrackerChart` |
| 地理分佈 | `DottedMap`、`TopoJSONMap` |

- 選定的圖種就是 Phase 2 去 blocks 找的類別（例如 `BarChart` 對 `/blocks/bar-charts`）。

## Good Example

- 這個例子是好的，因為先講清楚問題，再依資料形狀選圖。

```text
問題：近 12 個月各通路營收的走勢誰在成長 → 時間序列、多條序列比較 → LineChart → Phase 2 查 /blocks/line-charts
```

## Bad Example

- 這個例子是壞的，因為只因為 block 好看就選圖，沒對資料形狀。

```text
問題：近 12 個月各通路營收的走勢 → 看到 radar block 很漂亮 → RadarChart
```

# Rule 2 - 佔比類圖不承載時間或多類別

- Level: `MUST`
- `DonutChart`、`RadialBarChart` **NEVER** 用來表現隨時間的變化；時間軸一律用 `LineChart`／`AreaChart`／`BarChart`。
- 佔比超過 5 類，或類別之間差距小到肉眼分不出扇區大小時，改用排序過的 `BarChart`。
- 只有一兩個數字、沒有趨勢或比例可看時不畫圖，改用 KPI 卡或表格（回到 Phase 1 step 1 的判斷）。
- KPI 卡與 tooltip 上的數字、金額、百分比一律經共用 formatter 顯示，判準見 [[display-value-integrity]] § 格式化走單一 formatter（MUST）。

## Good Example

- 這個例子是好的，因為 9 個類別的佔比改用排序長條，數值差異看得出來。

```vue
<BarChart :data="sortedShares" :categories="{ share: { name: '佔比', color: chartColors.base } }" :y-axis="['share']" x-axis="channel" orientation="horizontal" :height="320" />
```

## Bad Example

- 這個例子是壞的，因為用甜甜圈畫 12 個月的趨勢，月份變成 12 個扇區。

```vue
<DonutChart :data="monthlyRevenue" :categories="months" />
```
