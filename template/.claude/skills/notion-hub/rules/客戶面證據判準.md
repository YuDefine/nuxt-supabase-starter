# Rule 1 - 客戶看得到的地方 NEVER 出現 github.com，網址只放 consumer prod 網域的完整 URL（D2）

- Level: `MUST`
- `備註` 與票內文 **NEVER** 出現 github.com（PR／CI run／tag／merge commit）——PR 連結只進 `PR` 欄，其餘留在 flow artifacts。`notion-sync.ts` 會拒寫。
- 客戶面的網址只放 consumer prod 網域（`.claude/consumer-meta.json` `deploy.prodUrl`）的完整 URL；**NEVER** 給相對路徑、staging 或其他網域。
- 截圖放內文（`file` 的「問題畫面」、`release` 的「驗收畫面（<tag>）」）。
- **NEVER** 手動 PATCH 把 GitHub 連結或其他網域塞進 `備註`／內文。

## Good Example

- 這個例子是好的，因為 PR 進 `PR` 欄，客戶面只有 prod URL。

```text
PR 欄：#412；備註：https://erp.example.tw/orders/2026-1001
```

## Bad Example

- 這個例子是壞的，因為客戶打不開也不該看 GitHub。

```text
備註：修好了，見 https://github.com/YuDefine/erp/pull/412
```

# Rule 2 - 客戶欄與客戶側轉移 machine NEVER 碰

- Level: `MUST`
- `附件` 是客戶欄，機器 **NEVER** 寫。
- 客戶側轉移（驗收中→完成、完成→封存）與 `預估完成日`（沒經人確認）**NEVER** 碰。
- 客戶把票推到完成／封存之後，machine 只做對帳（`reconcile`、`flow accept`），不反向改。

## Good Example

- 這個例子是好的，因為只讀客戶側狀態再對帳。

```text
票 = 完成（客戶推的）→ notion-sync.ts reconcile --work <id> → flow accept
```

## Bad Example

- 這個例子是壞的，因為 machine 替客戶把票推到完成。

```text
release 後順手 PATCH 狀態 → 完成
```

# Rule 3 - 客戶看得到的文字是定稿措辭，Pi 起草後主線 MUST 收斂重寫才寫入

- Level: `MUST`
- 適用：ticket 名稱、決策題、comment、`--title`（交付項目 Item）。
- 措辭用客戶的語言、不用技術術語；寫入前由主線定稿，**NEVER** 把 Pi 草稿原樣寫進 Notion。

## Good Example

- 這個例子是好的，因為主線把草稿收斂成客戶看得懂的一句話。

```text
Pi 草稿：「fix: order list N+1 query on expand」→ 主線定稿：「出貨單展開明細時載入太慢」
```

## Bad Example

- 這個例子是壞的，因為技術草稿直接成了客戶看到的標題。

```text
--title "fix N+1 in useOrderItems composable"
```

# Rule 4 - `notion-sync.ts file` 拒寫時照訊息修正來源，NEVER 繞過守門

- Level: `MUST`
- 三種拒寫與處置：
  - hub 未宣告 `ticketType` → 跑 `audit-notion-hub-schema.ts --hub <key>` 後補 `registry/notion-hubs.json`。
  - `--prod-url` 不是 consumer prod 網域（`.claude/consumer-meta.json` `deploy.prodUrl`）→ 換成 prod 網域上看得到問題的頁面；consumer 沒宣告 prodUrl 就 relay 給該 consumer 補。
  - `類型` 選項對不上 → schema drift，跑 schema 稽核並修 registry。
- **NEVER** 改用手動建頁或 PATCH 繞過拒寫。

## Good Example

- 這個例子是好的，因為依拒寫訊息改傳 prod 網域 URL。

```text
file 拒寫：--prod-url https://staging.erp.example.tw 不是 prod → 改 --prod-url https://erp.example.tw/orders
```

## Bad Example

- 這個例子是壞的，因為被拒後改用 ntn 手動建票，跳過證據守門。

```text
file 拒寫 → ntn api -X POST /v1/pages（備註帶 staging 網址）
```
