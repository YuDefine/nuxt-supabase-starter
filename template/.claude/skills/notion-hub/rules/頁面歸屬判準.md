# Rule 1 - 頁面歸屬只認 `notion-scope.ts` 的祖先鏈判定，NEVER 憑標題、內文或搜尋結果推斷屬於哪個客戶

- Level: `MUST`
- 所有 hub（每個客戶一個）與未登記的頁面（例如別的團隊、個人筆記）都在同一個 Notion workspace：`/v1/search` 會把它們混在一起回來，結果本身不帶歸屬。
- 歸屬的唯一來源是 `node ~/offline/clade/vendor/scripts/notion-scope.ts owner|search` 的 `owner`：頁面沿 parent 一路往上，碰到 `registry/notion-hubs.json` 某個 hub 的 `rootPageId` 才算屬於該 hub；走到 workspace 都沒碰到就是 `unregistered`，走不完就是 `unresolved`。
- 標題寫了誰的名字、內文提到哪台機器、看起來跟手上的事有關，都 **NEVER** 算歸屬證據。

## Good Example

- 這個例子是好的，因為標題看起來相關，但歸屬交給 script 判定。

```text
search 回「2026-10 IT 小組 … 工作內容彙報」→ notion-scope.ts search 標 owner=unregistered → 不屬於 fc，不採用
```

## Bad Example

- 這個例子是壞的，因為從標題與內文推斷歸屬。

```text
這頁是 Charles 的月報、內容提到 10/6 → 應該是 FC 的月報，FC 事件慣例是寫進月報
```

# Rule 2 - 範圍外頁面 NEVER 當參照、慣例證據或寫入目標

- Level: `MUST`
- 範圍內 = `owner` 等於本 consumer 宣告的 hub（`notion-scope.ts` 的 `inScope`／`inConsumerHub: true`）。其他 hub、`unregistered`、`unresolved` 一律是範圍外。
- 範圍外的頁面：
  - **NEVER** 拿來回答「本專案有哪些文件」「這個客戶通常怎麼做」，也 **NEVER** 從它歸納本客戶的慣例。
  - **NEVER** 寫入：寫任何頁面或 block 之前，對寫入目標跑一次 `notion-scope.ts owner <id>`，`inConsumerHub` 不是 `true` 就停下回報，不寫。
  - 使用者明講要用某個範圍外頁面時才可以用，回報時標出它屬於哪個 hub（或 `unregistered`）。
- consumer 沒宣告 hub（`consumerHub: null`）時沒有「範圍內」可言：每一頁照 `owner` 標出歸屬再用，**NEVER** 把不同 hub 的頁面混成一份結論。

## Good Example

- 這個例子是好的，因為寫入前先驗證寫入目標，範圍外就停。

```text
要在存取資訊頁插一條 → notion-scope.ts owner <page> → inConsumerHub: true → 派 notion-ops 插入
要改月報 → owner=unregistered → 停下：「這頁不在 fc hub 底下，不改」
```

## Bad Example

- 這個例子是壞的，因為範圍外頁面被當成本客戶的慣例，並被列入要寫的清單。

```text
候選要改的文件：① 存取資訊頁 ② 10 月工作彙報（照慣例新增一項）
```
