
# Rule 1 - 功能路由依決策樹由上而下，第一個命中即採用

- Level: `MUST`
- 順序即優先序；**NEVER** 跳過較前分支去挑「看起來比較順手」的較後分支。記下被跳過的較前分支與理由。
- 「整合第三方 API」指本系統**主動呼叫**外部 API；被外部系統呼叫（Webhook）屬第 2 類。

| # | 類別 | 條件 | 採用 |
| --- | --- | --- | --- |
| 1 | 外部整合 | 整合第三方 API＋寫入 DB | Hybrid：Edge Function 協調 → RPC 寫入，實作冪等性 |
| 1 | 外部整合 | 僅整合第三方 API | Edge Function，設定 Timeout／Retry |
| 2 | Webhook 處理 | 接收外部 Webhook | Edge Function：驗證簽名 → 200 OK → 非同步處理 |
| 3 | 檔案操作 | 檔案處理（壓縮、轉檔） | Edge Function（Stream） |
| 3 | 檔案操作 | 單純上傳／下載 | Client SDK 直連 Storage＋Bucket RLS |
| 4 | 敏感資料 | 操作涉及 API Keys／Secrets | Edge Function（環境變數） |
| 5 | 批次處理 | 資料源在 DB 內（每日結算） | Postgres RPC |
| 5 | 批次處理 | 外部匯入（CSV） | Edge Function（分批寫入） |
| 6 | 交易一致性 | 跨多張表寫入 | Postgres RPC（BEGIN…COMMIT） |
| 7 | 資料連動 | 寫入後觸發欄位更新（updated_at、計數） | Database Trigger，避免 cascade |
| 8 | 複雜統計 | 大量數據聚合 | Materialized View 或 RPC＋pg_cron 定期刷新 |
| 9 | 權限繞過 | 繞過 RLS（Admin 統計） | RPC（Security Definer），內部手動權限檢查 |
| 10 | 複雜查詢 | 動態 JOIN／CTE | RPC |
| 10 | 複雜查詢 | 固定複雜關聯 | View＋SDK 查詢 |
| 10 | 複雜查詢 | 過濾／全文檢索 | Client SDK（`ilike`、`textSearch`） |
| 11 | 標準 CRUD & Realtime | 即時更新 | SDK＋Realtime Channel |
| 11 | 標準 CRUD & Realtime | 標準 CRUD | Server API（client 直讀依 `modules.auth`，見 `server-api` skill） |
| 12 | 排程任務 | DB 維護 | pg_cron |
| 12 | 排程任務 | 外部邏輯 | Edge Function＋Cron |

## Good Example

- 這個例子是好的，因為它照順序先命中第 2 類，並把多表寫入當成命中分支內的實作細節，而不是改判第 6 類。

```text
需求：金流 Webhook 收單後寫入 orders、order_items、payments
命中：第 2 類 Webhook 處理 → Edge Function 驗證簽名 → 200 OK → 非同步處理
跳過：第 1 類（不是本系統主動呼叫第三方 API）
實作：非同步處理段以單一 RPC 寫三張表（交易一致性）
```

## Bad Example

- 這個例子是壞的，因為它跳過較前的第 2 類，直接以第 6 類決定整條路線，漏掉驗簽與快速回 200。

```text
需求：金流 Webhook 收單後寫入三張表
命中：第 6 類交易一致性 → Postgres RPC
```
