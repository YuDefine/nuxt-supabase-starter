
# Rule 1 - 展示的命令、輸出與 artifact 中每個秘密 MUST 先換成 `<REDACTED>`

- Level: `MUST`
- 本 skill 會一路貼出迴圈命令、輸出與擷取到的 artifact。貼出之前，把每一個秘密原地換成 `<REDACTED>`：API key、token、cookie、session id、密碼、連線字串裡的帳密、簽章 URL 的 query 參數。
- 建迴圈時讓憑證留在環境變數裡（`$API_TOKEN`、`.env` 由 runtime 載入），命令列只引用變數名稱。這樣 invocation 本身就不帶秘密，展示時不必事後挖洞。
- 擷取來的 artifact（HAR、request dump、log、core dump）通常夾帶 auth header 與 cookie：只引用帶有訊號的那幾行，**NEVER** 整份貼出再說「裡面有 token 請忽略」。
- 遮蔽適用於本 skill 所有對外輸出：對話回覆、寫進 plan 或 PR 的證據、Phase 3 給使用者看的假設清單。

## Good Example

- 這個例子是好的，因為憑證走環境變數，輸出只引用帶訊號的行，殘留的秘密已遮蔽。

```text
$ curl -sS -H "Authorization: Bearer $API_TOKEN" -X POST http://localhost:3000/api/orders -d @fixture/order.json
HTTP/1.1 500
set-cookie: sb-access-token=<REDACTED>; Path=/
{"statusCode":500,"message":"Cannot read properties of undefined (reading 'id')"}
```

## Bad Example

- 這個例子是壞的，因為 token 直接寫在命令列，整份 response header 原樣貼出。

```text
$ curl -H "Authorization: Bearer eyJhbGci..." http://localhost:3000/api/orders
set-cookie: sb-access-token=eyJhbGciOi...; sb-refresh-token=v1.Mr5...
（以下 40 行 header 全文）
```

# Rule 2 - 遮蔽後的輸出不足以判斷時 MUST 明說並向使用者要

- Level: `MUST`
- 如果遮蔽之後剩下的內容不夠診斷（例如 bug 正好出在 token 格式、過期時間或簽章），明說「遮蔽後無法判斷 X」，向使用者要所需的最小資訊（例如只要 token 的 `exp` claim、只要 header 名稱），**NEVER** 為了繼續而取消遮蔽。

## Good Example

- 這個例子是好的，因為它說出缺什麼，並只要最小欄位。

```text
遮蔽後看不出 401 是過期還是簽章錯。請提供 token decode 後的 exp 與 iss 兩個欄位（不必給 token 本身）。
```

## Bad Example

- 這個例子是壞的，因為它為了判斷而把秘密原文貼回對話。

```text
為了確認是不是過期，我把完整 JWT 貼出來 decode：eyJhbGciOi...
```
