# 授權邊界與移植差異

## Rule 1：目的 repo 可見度

**Why**：Commercial License 允許用在商業專案，但原始碼不能公開散布；PUBLIC repo 一旦收進衍生程式碼就等於公開了。

**MUST**

- 動手前跑 `gh repo view <owner>/<repo> --json visibility --jq .visibility`，結果是 `PRIVATE` 或 `INTERNAL` 才可以把以參考實作為底的程式碼寫進去。
- 查不到可見度（沒有 remote、`gh` 沒權限）就當 PUBLIC 處理。

**NEVER**

- **NEVER** 把參考實作的原始碼或改寫後的程式碼寫進 PUBLIC repo，包括 `YuDefine/nuxt-supabase-starter`（PUBLIC＋`public_mode`）與 clade 的 rule／snippet。PUBLIC repo 只照 clade rule 的判準自己寫。
- **NEVER** 把 clone 下來的參考實作放進 consumer repo 的工作目錄或 commit 進去。

## Rule 2：移植差異

**Why**：scaffold 綁 Cloudflare 與 SQLite，fleet 多數 consumer 跑 Supabase；直接照抄會帶進目的 repo 沒有的綁定。

**MUST**

- 照下表逐項判，目的 repo 本來就用同一個東西的才照用：

| 參考實作用的 | 在哪 | 目的 repo 跑 Supabase 時 |
| --- | --- | --- |
| drizzle `sqlite-core`＋`drizzle-orm/d1` | `server/db/schema/`、`server/utils/db.ts` | 照目的 repo 既有的 DB 存取方式（Supabase client 或 `pg-core`）；schema 改動照 `migration` rule |
| R2 檔案儲存 | `server/utils/storage.ts`、`server/api/uploads/` | Supabase Storage |
| CF Queues 事件派送 | `server/events/`、`server/plugins/events-queue-consumer.ts` | 同步執行，或目的 repo 既有的背景工作機制；不新開 queue |
| Better Auth＋organization plugin | `server/utils/auth.ts`、`app/utils/dashboard/auth-client.ts` | 照目的 repo 既有的 auth module rule；權限檢查同時對照 `rls-policy` 決定哪層擋 |
| nuxt-charts v2 | `app/utils/dashboard/charts.ts`、`server/api/dashboard/revenue.get.ts` | 照 `nuxt-charts` skill 用 v3 |
| 英文介面字串 | 各元件 | 照目的 repo 的語系與 i18n 慣例 |

- clade rule 與參考實作做法不同時以 clade rule 為準，並在 PR 說明寫出差異。

## Rule 3：來源註記

**Why**：之後 layer 移植或上游更新時，要找得到哪些檔是從參考實作來的、對照的是哪一版。

**MUST**

- 以參考實作為底的檔第一行寫註記，註解語法依檔案類型：

```text
dashboardstack: <參考實作路徑>@<layer repo commit 前 7 碼>
```

| 檔案類型 | 寫法 |
| --- | --- |
| `.vue`、`.html`、`.md` | `<!-- dashboardstack: … -->` |
| `.ts`、`.js`、`.mjs` | `// dashboardstack: …` |
| `.css` | `/* dashboardstack: … */` |
| `.sql`（migration） | `-- dashboardstack: …` |
| `.yaml`、`.yml` | `# dashboardstack: …` |
| `.json` 等不能寫註解的檔 | 不改檔，改在 PR 說明列「`<目的路徑>` ← `dashboardstack: …`」 |

- 一個檔參考多個來源時用逗號分隔。

## Rule 4：clone 前驗 layer repo 可見度

**Why**：授權邊界靠 layer repo 保持 PRIVATE；它若被誤改成 PUBLIC，原始碼已經外流，不能再當成合法來源繼續用。

**MUST**

- 在 session scratchpad 底下跑下面這段（clone 目錄 MUST 在任何 git repo 之外）。印 `NOT-PRIVATE <可見度>` 或 `CLONE-FAILED`（404、未登入 gh）就停下回報，**NEVER** 改去別處找副本：

```bash
v=$(gh repo view YuDefine/nuxt-dashboard-layer --json visibility -q .visibility 2>/dev/null)
[ "$v" = PRIVATE ] || { echo "NOT-PRIVATE ${v:-查不到}"; exit 1; }
D="$(mktemp -d "<session scratchpad>/dsl.XXXXXX")/nuxt-dashboard-layer"
gh repo clone YuDefine/nuxt-dashboard-layer "$D" -- --quiet || { echo "CLONE-FAILED"; exit 1; }
echo "OK $(git -C "$D" rev-parse --short=7 HEAD)"
```

- 來源註記（Rule 3）的 commit 用 `OK` 印出的短 sha。
