
# Rule 1 - `/track` 的參數 MUST 先當查詢比對，對不到才當標記標題

- Level: `MUST`
- 沒有參數 → `list`（未結的，加上 7 天內結案還沒看過的）。Charles 說「全部」→ `list --all`。
- 參數是追蹤 id（`t-` 開頭）、或明說「看／查／切到／打開 X」→ 拿 X 查（Rule 2）。
- 參數明說「標／追蹤／盯著 X」→ 標記，走 `rules/追蹤標記判準.md`。
- 其他文字 → 先跑 `show <文字>` 比對：對到一件照 Rule 2 處理；對到多件把候選列給 Charles 選；對到 0 件才當成標記的標題走 Phase 1。**NEVER** 不比對就直接 `mark`——同一件事會被登記兩次，而 Charles 要的是進度。

## Good Example

- 這個例子是好的，因為「dashboard 追蹤區」先拿去比對，對到既有委託就回進度，沒有重複登記。

```bash
node ~/offline/clade/vendor/scripts/tracked-session.ts show 'dashboard 追蹤區'
```

## Bad Example

- 這個例子是壞的，因為沒比對就標記，委託帳多一筆重複的，Charles 也沒拿到進度。

```bash
node ~/offline/clade/vendor/scripts/tracked-session.ts mark --title 'dashboard 追蹤區'
```

# Rule 2 - 查到一件：還在跑就 `open` 切過去，已結束就 `show`

- Level: `MUST`
- 還沒結案、列表顯示在本機的 pane → `open <id>`：script 會核對 pane 上的 session 再 `herdr tab focus`；pane 已不在、或在另一台機器時它會改印位置與接續 prompt。
- 已結案、在等 Charles 回答、或 Charles 只問結論 → `show <id>`，原樣轉給 Charles（結論、接續檔、接續 prompt）。
- `show`／`open` 都會把這件標成看過，之後預設的 `list` 不再列它；**NEVER** 為了「先看看」而對 Charles 沒問的件跑 `show`。
