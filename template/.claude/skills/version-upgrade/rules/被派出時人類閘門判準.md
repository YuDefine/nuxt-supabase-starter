# 被派出時人類閘門判準

觸發點：SKILL.md Step 0（每一次啟動本 skill），`CLADE_DISPATCH_ID` 非空時；之後每碰到一個「等 user／問 user／runtime-native question interface」閘門再讀一次。

# Rule 1 - 被派出的 pane 碰到人類閘門一律送題交回，NEVER 自行越過

- Level: `MUST`
- 本 skill 自 2026-11-19 起由派工者代打（Charles「納入代打」：clade 主持者與 HQ 走同一條路徑派 worker）：brief 第一行 `/version-upgrade --reason <理由> --scope <範圍>`，helper 把那一行當使用者指令打進 pane。代打只換掉「誰打這行指令」，**NEVER** 換掉本 skill 裡任何一個人類閘門。
- `CLADE_DISPATCH_ID` 非空＝被派出的 pane，本 skill 各處寫「MUST 等 user 拍板／選／確認」「runtime-native question interface」「問 user」的地方，一律改走下表；**NEVER** 用 AskUserQuestion、**NEVER** 在 final response 裡問、**NEVER** 自己選一個選項繼續。

評估：first-match；以上皆非 → G*

| id | 閘門性質 | 出口 |
| --- | --- | --- |
| G1 | 本輪（同一份計畫檔、同一個 dispatch 鏈）為**這一個**閘門送出的題已有答覆，答覆由 `--continue` 或續接 brief 逐字帶回並附該題題號；G2、G3、G* 的閘門只認 Charles 本人的答覆（coordinator 代答不算，照原列重送） | 視為已答，只照答覆涵蓋的列走；其餘列照 G2–G4。**NEVER** 沿用別輪、別個 consumer 或別份計畫的舊答覆 |
| G2 | 跨大版本（`major`、換發行線、framework migration）、正式機（staging／prod／`role: dev` 以外的遠端主機）、更新政策（Step 0.1 `rules/更新政策詢問判準.md`） | `--complete blocked --decision-for charles`，**NEVER** 交給 coordinator 裁決 |
| G3 | 其餘本 skill 寫明要 user 拍板的閘門（Step 0 判不出 route、B 計畫確認、F.5 plan gate、F.8.2 push gate、C.5 research 仍失敗、K4／K* 衝突、deprecated 換套件、P.5 定目標） | `--complete blocked --decision-for charles`；等的時間長或要排進 Charles 佇列時改 `flow ask`（選項照該閘門原本的選項列）後以 `--wait-until` 交回 |
| G4 | 只是載體、重派、環境問題（S*、watcher 失敗分流） | 照 `--complete blocked --decision`（預設問 coordinator） |
| G5 | 流程要再派 pane（FR.3 relay 各 consumer、F.6 長駐 session、C.2／C.4 的 Herdr 載體）——被派出的 pane 再派會被 helper 以 `nested_dispatch_refused` 拒 | C.2／C.4 改 in-process `sonnet-implementer`（brief 帶 `routing-row:`）或主線自己做；F.6 只用 in-process 具名 subagent（本 pane 留著做 F.7 收齊與 F.8 push gate，F.8.2 照 G3 送題）；只有 FR.3 把每家一份 brief（首行 `/version-upgrade --reason <理由> --scope consumer`）寫進計畫檔，commit＋push 後 `--complete success --followup-brief <計畫檔絕對路徑>` 交回派工者逐家派（FR.4 收斂由派工者接手）。**NEVER** 自己 fanout |
| G* | 判不出屬哪一類 | 照 G2 送 Charles |

- 送題時 `--decision` 照 handoff helper 的題面格式：先一兩句前提（現況、為什麼卡在這），再一句問句；選項用 `--decision-option`，沿用該閘門原本的選項（例：F.5 的「全部 sweep／先挑一個試／改 BC 解析／中止」）。計畫檔已寫好的先 commit＋push，再送題。
- `--complete blocked` 送出後本棒結束，答覆由 `--continue` 帶回；**NEVER** 等答覆時自己續做下一個 Phase。
- 本 skill 的 `disable-model-invocation` 保留：被派出的 pane 只認派工者打進來的那一行指令，**NEVER** 由模型自行呼叫或讀檔照跑。

## Good Example

- 這個例子是好的，因為被派出的 pane 到 F.5 停下來送題，選項沿用 plan gate 原本的四項。

```text
CLADE_DISPATCH_ID=… → F.5 計畫檔 commit＋push →
herdr-session-handoff.ts --complete blocked --decision-for charles \
  --decision '@nuxt/ui 4.3 命中 6 個 consumer，計畫表已寫好。要怎麼推？' \
  --decision-option '全部 sweep :: 六家並行升' --decision-option '先挑一個試 :: 先跑一家再決定' …
```

## Bad Example

- 這個例子是壞的，因為被派出的 pane 把「MUST 等 user 選」當成沒人可問，自己選了全部 sweep。

```text
CLADE_DISPATCH_ID=… → F.5「沒有 user 在線，照推薦選 [1] 全部 sweep」→ F.6 fan-out
```

- 這個例子是壞的，因為跨大版本的決定交給 coordinator 裁決，繞過了 Charles。

```text
Nuxt 4 → 5 → --complete blocked --decision '要升 Nuxt 5 嗎？'（沒帶 --decision-for charles）
```
