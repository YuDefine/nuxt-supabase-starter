# Rule 1 - 經 mise 安裝指定版本的 cf，NEVER 全域 npm 安裝

- Level: `MUST`
- 安裝與升級一律 `mise use -g npm:cf@1.0.0-beta.5`，再以 `cf --version` 確認。
- 必須指定版本：beta 期 `mise latest npm:cf` 解析到舊的 `0.15.0`，不是本 skill 實測的版本。
- **NEVER** `npm i -g cf`。

## Good Example

- 這個例子是好的，因為經 mise 釘版本並確認。

```bash
mise use -g npm:cf@1.0.0-beta.5
cf --version
```

## Bad Example

- 這個例子是壞的，因為全域 npm 安裝又沒指定版本。

```bash
npm i -g cf
```

# Rule 2 - 先 void 後 cf，token 照帳號位置表取，多帳號異動前確認身分

- Level: `MUST`
- 工具序：`void` 能做的用 `void`；void 不涵蓋的才用 `cf`；兩者都沒有才 HTTP API（`cloudflare-workers.md` § 8）。**NEVER** 用 wrangler。
- token 位置（帳號 → token，本表是唯一出處；自己去取，**NEVER** 再問 Charles 要 token 值）：

  | 帳號 | token 位置 | 取法與限制 |
  |---|---|---|
  | FC 公司帳號 | Notion FC 公司層 Secret 頁，block `333b7911-1721-8007-91c6-cd6301aca264` | 只准 notion-hub `references/ntn-cookbook.md` § 讀 Secret 的「指定 block id → jq 取值 → export」；**NEVER** 列這個 block 或 Secret 頁的 children、**NEVER** 整頁讀取 |
  | YuDefine（Abcd854884） | `~/.config/clade/cf-yudefine-token` | `export CLOUDFLARE_API_TOKEN="$(cat ~/.config/clade/cf-yudefine-token)"`；**NEVER** `cat` 到螢幕 |
  | hyperdrive-trial | `~/.config/clade/hyperdrive-trial/cloudflare.env` | 試驗用，**NEVER** 當通用 token；沒有 Access IdP 權限，Access 相關操作改用該帳號的正式 token |

- 擋列 children 的 hook（hub-core `pre-bash-notion-secret-read-gate.sh`）的實際範圍：擋 Secret 頁本身與其子區塊／子頁的 `blocks/<id>/children`、`ntn pages get`（子區塊靠 `ntn api` 往上查 parent 鏈）。缺口：只在載入 hub-core 的 consumer 與 clade home 生效，**yudefine-hq 等沒啟用 hub-core 的目錄不載入**；id 放變數分兩次 tool call、腳本檔、`node -e`、Notion MCP 也不攔。沒被擋不代表可以，取法照上表。
- 表裡沒有的帳號：向 Charles 要一次該值的位置（Notion 區塊給「Copy link to block」連結），登記進上表再用。值只以環境變數注入當次 shell，**NEVER** 寫進檔案、commit、argv 或回報。
- 認證用 `CLOUDFLARE_API_TOKEN`（account 層操作另設 `CLOUDFLARE_ACCOUNT_ID`），或 `cf auth login`／`--profile`。
- 機器上有多個帳號或 profile 時，任何異動前都必須先 `cf auth whoami`，確認是目標帳號。

## Good Example

- 這個例子是好的，因為 void 做不到才用 cf，FC 公司帳號的 token 照位置表指定 block id 取值、只進環境變數，異動前先確認身分。

```bash
export CLOUDFLARE_API_TOKEN="$(timeout 30 ntn api "/v1/blocks/333b7911-1721-8007-91c6-cd6301aca264" < /dev/null \
  | jq -r '.[.type].rich_text | map(.plain_text) | join("")')"   # ntn-cookbook § 讀 Secret；值不經螢幕
cf auth whoami
cf <void 不涵蓋、cf cli search 找到的指令>
```

## Bad Example

- 這個例子是壞的，因為 void 做得到的 D1 migration 改用 cf、token 貼在命令列（留在 shell history），且沒確認身分就異動；為了找 token 去列 Secret 頁 children 同樣是壞的（整頁值會印進 transcript）。

```bash
CLOUDFLARE_API_TOKEN=<貼上的值> cf d1 migrations apply <uuid> --dir migrations
```

# Rule 3 - 找指令先搜尋再看 help，查詢字串不帶識別資訊

- Level: `MUST`
- 第一次用某個子指令或指令失敗時：`cf cli search "<動作 + 資源類型>"` → `<指令> --help`；API 欄位用 `cf schema <指令去掉開頭 cf>`。
- 搜尋字串只寫動作與資源類型；**NEVER** 帶 domain、account／zone／resource ID、email、token。

## Good Example

- 這個例子是好的，因為搜尋字串只描述動作與資源類型。

```bash
cf cli search "purge cache zone"
cf <search 回傳的指令> --help
```

## Bad Example

- 這個例子是壞的，因為搜尋字串帶了 domain 與 zone ID。

```bash
cf cli search "purge cache example.com 023e105f4ecef8ad9ca31a8372d0c353"
```

# Rule 4 - 輸出沒有 `.result` 外層，`--dry-run` 不經 API 驗證

- Level: `MUST`
- 成功時 stdout 就是 API 回應的 `result` 本體（**沒有** `.result` 外層），API 錯誤時 exit 非 0；`jq` 路徑照此寫。
- 異動類指令必須先跑 `--dry-run`；它只在本機印出將送出的 request，不經 API 驗證。
- 其他檔（skill、snippet、runbook）的 cf 異動範例為了簡潔可能省略 `--dry-run`，**NEVER** 讀成可跳過。

## Good Example

- 這個例子是好的，因為 `jq` 直接取本體欄位，異動前先 dry run。

```bash
cf d1 list --name app-db | jq -r '.[0].uuid'
cf <異動指令> <參數…> --dry-run
```

## Bad Example

- 這個例子是壞的，因為照 REST API 習慣多寫了 `.result`，且直接實跑異動。

```bash
cf d1 list --name app-db | jq -r '.result[0].uuid'
cf <異動指令> <參數…>
```
