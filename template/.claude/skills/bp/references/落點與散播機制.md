# 落點與散播機制（查表）


> 本檔只放查表資料：各落點怎麼到達 consumer、何時載入，以及 `registry/conventions.json` 的欄位。判準（Q1／Q2／Q3、tie-breaker、縱向下推、反模式）在 `rules/落點路由判準.md`。

## 7 個落點

| # | 落點 | 到達 consumer 的機制 | 載入時機 |
| --- | --- | --- | --- |
| 1 | `rules/core/*.md` | 逐 target 投影成語意分域的 `clade-*` rule-skill（Claude `.claude/skills/clade-*`、agents `.agents/skills/clade-*`；分域與 description 由 `adapters/rule-skills.ts` 決定），無條件收；**不**寫進 `.claude/rules/`，也不安裝 scoped-rule hook（`adapters/README.md`） | 沒有 session 起手自動載入：rule 內文只在該 `clade-*` skill 被叫起後，依 SKILL.md 的 READ 條目讀。無 `paths:` → 列在「本 skill 啟用即讀」；有 `paths:` → 列成「READ 若要讀或改 〈paths〉」，**`paths:` 只是 skill 內的 READ 條件，不會因編輯命中檔案而自動載入**；有 `moment` 的 rule 另併進 skill description 的 `Also use when:` |
| 2 | `rules/modules/<group>/<variant>/*.md` | 同上，但只在 consumer manifest（canonical `.clade/manifest.json`，legacy `.claude/hub.json`）的 `modules[group]` 選了該 variant 才收 | 同上 |
| 3 | `capabilities/core/{skills,commands,agents,hooks}/`（含 skill 的 `rules/`、`templates/`、`scripts/`、`references/`） | plugin cache（`claude plugin update`）；**consumer 需重啟 session 才生效** | skill／command 被呼叫時；skill 的 `rules/` 在 SOP step 讀到時 |
| 4 | `claude-md/core-snippets/*.md` | 不作為新落點：always-on 內容走落點 1 無 `paths:` | — |
| 5 | `vendor/{scripts,actions,git-hooks,oxc-shared,ci,...}` | `sync-vendor.ts`（targets 定義在 `scripts/lib/vendor-targets.ts`） | 被執行時 |
| 6 | `vendor/snippets/<topic>/` | **不散播**（唯一例外：`manual-review-enforcement/patterns.json`） | 由 rule／skill 用絕對路徑指過去，讀的當下 |
| 7 | `docs/`（`rule-rationale/`、`golden-paths/`、`conventions/`、`decisions/`、`sweeps/`） | **不散播** | 同上 |

落點 3 的 hook 分兩種：command hook（shell／script，隨投影到各 runtime）與 mod（Claude Code 的 function-hooks plugin，**只在 Claude Code 載入**，其他 harness 收不到）。兩者怎麼選見 `rules/落點路由判準.md` Rule 9。

**加映（方向相反，不是給 consumer 讀的）**：`registry/*.json` 是 clade 端的治理 metadata。`conventions.json` 是唯一機讀的最佳實踐目錄，`consumers.json`／`audits.json` 描述 fleet 與稽核接線。

## `registry/conventions.json` 欄位

```
convention_id / name / layer / description
variants[] { variant_id, description, maturity: stable|starter|legacy|experimental, requires_modules, migration_to }
rule_refs[] / snippet_refs[] / audit_script / doc_ref
```

讀這份目錄的管線：`bp-scan.ts --plan`（新專案該套什麼）、`convention-conformance-audit`（誰採用了哪個 variant）。
