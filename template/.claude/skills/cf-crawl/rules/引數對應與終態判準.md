
# Rule 1 - 只送使用者給的引數，預設值以本表為準

- Level: `MUST`
- 引數與 request body 的對應（`crawl.py start` 依此組 body；手動組 body 時同樣適用）：

| `/cf-crawl` 引數 | body 欄位 | 未給時 |
| --- | --- | --- |
| 第一個位置參數 URL | `url` | 問使用者，NEVER 猜 |
| `--limit N`／`-l N` | `limit` | 20（API 自己的預設是 10） |
| `--depth N`／`-d N` | `depth` | 不送（API 預設 100000） |
| `--include "p1,p2"`／`--exclude "p1,p2"` | `options.includePatterns`／`options.excludePatterns` | 不送 |
| `--no-render` | `render: false` | 不送（headless 瀏覽器） |
| `--source sitemaps\|links\|all` | `source` | 不送（`all`） |
| `--since DATE` | `modifiedSince`（ISO 日期或 Unix 秒，轉成 Unix 秒） | 不送 |
| `--output DIR`／`-o DIR` | 不進 body，`fetch` 的輸出目錄 | `.crawl-output` |
| `--merge` | 不進 body，`fetch` 合併成單檔 | 每頁一檔 |

- `formats` 固定 `["markdown"]`。
- pattern 語意：`*` 不跨 `/`、`**` 跨 `/`；exclude 優先於 include。
- `--no-render` 只拿靜態 HTML，較快較省但抓不到 JS 渲染的內容；靜態站才建議用。

## Good Example

- 這個例子是好的，因為只送了使用者給的旗標，`limit` 用 skill 預設 20。

```bash
# /cf-crawl https://docs.example.com --include "/guide/**"
uv run scripts/crawl.py start --url https://docs.example.com --include "/guide/**"
# body: {"url":"https://docs.example.com","limit":20,"formats":["markdown"],"options":{"includePatterns":["/guide/**"]}}
```

## Bad Example

- 這個例子是不好的，因為使用者沒要求卻送了 `render:false` 與 `depth`，JS 渲染的文件站會抓到空殼。

```bash
uv run scripts/crawl.py start --url https://docs.example.com --no-render --depth 2
```

# Rule 2 - 終態決定取回或回報，部分結果也要取回

- Level: `MUST`
- 終態與處置：

| status | 意義 | 處置 |
| --- | --- | --- |
| `running` | 進行中 | 繼續輪詢 |
| `completed` | 完成 | 進 Phase 4 取回 |
| `cancelled_due_to_limits` | 撞到頁數或額度上限 | 照樣取回已完成的頁，回報時說明被截斷 |
| `cancelled_due_to_timeout` | 超過 7 天上限 | 照樣取回已完成的頁，回報時說明逾時 |
| `errored` | 失敗 | 不取回，回報 job ID 與錯誤內容 |

- records 以 `?status=completed&limit=50&cursor=<CURSOR>` 分頁；帶 `modifiedSince` 時未變更的頁列在 `status=skipped`，robots.txt 擋下的 URL 是 `status=disallowed`，兩者都要在回報寫出數量。
- 爬蟲遵守 robots.txt（含 crawl-delay）；`disallowed` 多時向使用者說明是 robots.txt 擋下。
- Free plan 每天 10 分鐘瀏覽器時間、結果保留 14 天、單頁上限 10 MB；大量爬取前提醒使用者額度。

## Good Example

- 這個例子是好的，因為截斷的 job 仍取回並說明原因。

```text
Status: cancelled_due_to_limits | Finished: 20/20
→ uv run scripts/crawl.py fetch --job <JOB_ID>
→ 回報：保存 20 頁到 .crawl-output/，skipped 0、disallowed 3；頁數撞到 --limit 20 被截斷。
```

## Bad Example

- 這個例子是不好的，因為把非 `completed` 一律當失敗，丟掉已爬完的頁。

```text
Status: cancelled_due_to_limits → 回報「crawl 失敗」並結束
```
