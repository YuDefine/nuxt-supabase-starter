# 應有而缺的依賴：回報並當場補上

應有而缺的依賴或工具：回報主管，並當場安裝修復；**NEVER** 靜默改走替代路徑。只有明定規則列出的情況才准替代，替代時必須大聲記錄。

「應有」指本件的設計、workflow 或既有文件已假設它存在（例：workflow 呼叫 `gh`、runner 文件寫該機器有它）。缺的是環境，不是設計：補環境，不要改設計去遷就缺口。

## 怎麼做

1. **回報**：同一則訊息說清楚缺什麼、在哪台、怎麼發現的；有主管就送主管，沒有就寫進收尾回報。
2. **當場裝**：授權範圍內（該專案或該主機的安裝慣例允許）直接裝，裝完以實際執行環境驗證（例：用 runner 的 hermetic PATH 跑 `gh --version`），再重跑原本失敗的那件事。主管或規約明禁動基礎設施時，先回報、請求授權，**不是**改走別條路。
3. **同類盤點**：找出其他同樣假設該依賴的主機／槽／環境，缺的一併列出。
4. **程式端大聲失敗**：工具缺失時 exit 非 0，stderr 寫明缺什麼、在哪台；**NEVER** 吞錯、**NEVER** 靜默降級成較弱的做法。

## 例外

規約逐字列出的替代路徑（例：某檢查在無網路環境明定改跑離線版）才准用，且使用時必須在輸出裡大聲記錄「缺什麼、改用什麼、依據哪條規約」。沒有規約列出的替代，一律當缺口處理。

## 為什麼是文字規約
